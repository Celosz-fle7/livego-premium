
# GitHub Actions Build Guide for Nobuzero

This guide explains how to configure GitHub Actions for automatic APK builds using Repository Secrets.

## Configuration (Repository Secrets)

Before running the workflow, ensure the following secrets are added to your GitHub repository (**Settings > Secrets and variables > Actions**):

| Secret Name | Description |
|-------------|-------------|
| `LIVEGO_BASE_URL` | The base URL of the Nobuzero API. |
| `LIVEGO_NOBUZERO_BASE_URL` | Secondary base URL for legacy compatibility. |
| `LIVEGO_USER_ID` | Your User ID from the Nobuzero Admin UI. |
| `LIVEGO_SECRET` | Your Secret Key from the Nobuzero Admin UI. |
| `LIVEGO_RELEASE_KEYSTORE_BASE64` | Base64 encoded `.jks` release keystore file. |
| `LIVEGO_RELEASE_STORE_PASSWORD` | Password for the keystore. |
| `LIVEGO_RELEASE_KEY_ALIAS` | Key alias for the release key. |
| `LIVEGO_RELEASE_KEY_PASSWORD` | Password for the release key. |

## Workflow Security

- **Credential Integrity**: The build workflow will fail immediately if any of the required secrets are missing.
- **Privacy**: User IDs and Secrets are passed directly to the Flutter compiler via `--dart-define` and are never printed to the console logs.
- **Artifacts**: APKs generated by GitHub Actions are uploaded as internal artifacts and are not publicly released.

## API Contract and Signature

The Nobuzero v2 API requires dynamic HMAC-SHA256 signatures for every request.
- **Payload Formula**: `METHOD:FULL_PATH_WITH_QUERY:TIMESTAMP`
- **Timestamp**: Unix milliseconds.
- **Header**: `X-Signature: HMAC-SHA256(LIVEGO_SECRET, payload)`.

## Release Notes

Test credentials provided via repository secrets are for internal testing only. After verification, the Admin UI user can be deactivated to ensure security.
